## 1. What was run

Harness entry: `issue_3209.py::repro_3209`

Trigger, as recorded during the study:

```text
Concurrently issue 3 GET /mcp requests on the same OAuthClientProvider (/mcp each sleeps 0.3s)
```

## 2. What the reporter described

context.lock(anyio.Lock) wraps the entire flow in _auth_flow, including `response = yield request`, and is released only after the response returns; concurrent requests are fully serialised, and long-lived SSE streams monopolise the lock and block other requests, without throwing any error

## 3. What we captured

Captured in our run (evidence tier A).

```
3 concurrent GET /mcp: elapsed 0.624/0.935/1.247s (fully serialised; parallel would be ~0.3s), total 1.248s, 0 errors
```

## 4. Why it happens

`_auth_flow` wraps the entire flow in `async with self.context.lock` (anyio.Lock), including `response = yield request`, so the lock is not released until the response returns; concurrent requests on the same provider are fully serialized (measured 3 concurrent at 0.62/0.94/1.25s), and a long-lived SSE stream monopolizes the lock and blocks other requests without throwing any exception — a silent failure.
