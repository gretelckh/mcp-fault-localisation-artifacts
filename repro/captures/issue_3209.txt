## 1. What was run

Harness entry: `runner/repro_pending/repro_oauth_lifecycle.py::test_3209`

Trigger, as recorded during the study:

```text
同一 OAuthClientProvider 上并发 3 个 GET /mcp（/mcp 各 sleep 0.3s）
```

## 2. What the reporter described

context.lock(anyio.Lock) 在 _auth_flow 中包住整个流程，包括 `response = yield request`，直到响应返回才释放；并发请求被完全串行化，长连接 SSE 流会独占锁并阻塞其它请求，且不抛任何错误

## 3. What we captured

Captured in our run (evidence tier A).

```
3 concurrent GET /mcp: elapsed 0.624/0.935/1.247s (fully serialised; parallel would be ~0.3s), total 1.248s, 0 errors
```

## 4. Why it happens

`_auth_flow` 用 `async with self.context.lock`（anyio.Lock）包住整个流程，包括 `response = yield request`，锁要等响应返回才释放；同一 provider 上的并发请求被完全串行化（实测 3 并发 0.62/0.94/1.25s），长连接 SSE 流会独占锁阻塞其它请求，且不抛任何异常，属静默失效。
