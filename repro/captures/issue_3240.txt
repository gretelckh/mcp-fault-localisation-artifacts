## 1. What was run

Harness entry: `issue_3240.py::repro_3240`

Trigger, as recorded during the study:

```text
The authorization server is mounted under the path (http://127.0.0.1:9999/auth); a refresh is triggered when the process restarts and metadata has not yet been discovered.
```

## 2. What the reporter described

Refresh endpoint resolution only recognizes oauth_metadata.token_endpoint, otherwise it falls back to urljoin(origin, '/token'); after a restart, metadata has not yet been discovered, so the refresh POST hits the root path /token (it should be /auth/token), the 404 causes the refresh to fail and the bare HTTP 404 is leaked to the caller.

## 3. What we captured

Captured in our run (evidence tier B).

```
AS mounted under /auth; refresh POST hit '/token' (expected '/auth/token'); final status=404, no MCP-layer error raised
```

## 4. Why it happens

Refresh endpoint resolution only recognizes `oauth_metadata.token_endpoint`, otherwise it falls back to `urljoin(origin, '/token')`; after a process restart, when metadata has not yet been discovered, a refresh that the authorization server mounts under the `/auth` path is sent to the root path `/token`, the 404 causes the refresh to fail and the bare HTTP 404 is leaked directly to the caller — a caller-exception (endpoint resolution defect).
