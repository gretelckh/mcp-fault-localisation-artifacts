检查 mcp.server.auth.middleware.bearer_auth._send_auth_error 构造 WWW-Authenticate

## 2. What the reporter described

RequireAuthMiddleware 的 _send_auth_error 构造 WWW-Authenticate 时只含 error/error_description(可选 resource_metadata)，从不含 RFC 6750 要求的 scope= 参数，导致客户端无法据挑战限定重新授权所需 scope

## 3. What we captured

Captured in our run (evidence tier B).

```
_send_auth_error: www_auth_parts=[error, error_description(, resource_metadata)] -> Bearer ...; scope= 参数缺失
```

## 4. Why it happens

`RequireAuthMiddleware._send_auth_error` 构造 `WWW-Authenticate` 时只含 error/error_description（可选 resource_metadata），从不含 RFC 6750 §3 要求的 `scope=` 参数；客户端据挑战重授权时无法得知所需 scope，step-up 授权范围被降级。报在 Server 层（层面正确），但挑战信息被降级，属 single-layer 泛化/掩蔽。
