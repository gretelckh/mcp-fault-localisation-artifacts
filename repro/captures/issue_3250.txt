Trigger, as recorded during the study:

```text
storage 预置已过期 token(expires_in=-3600)+refresh_token，模拟进程重启后发第一个请求
```

## 2. What the reporter described

_initialize() 只从 storage 恢复 current_tokens/client_info，从不调用 update_token_expiry()，token_expiry_time 保持 None；is_token_valid() 因 `not self.token_expiry_time` 把过期 token 判为有效，于是直接发出陈旧 Bearer，且全程 0 次 refresh —— 透明刷新在重启后失效

## 3. What we captured

Captured in our run (evidence tier B).

```
after _initialize: token_expiry_time=None; is_token_valid()=True (token expired 1h ago); Authorization sent=Bearer at-stale; refresh requests=0; final status=200
```

## 4. Why it happens

进程重启后 `OAuthClientProvider._initialize()` 只从 storage 恢复 `current_tokens`/`client_info`，从不调用 `update_token_expiry()`，`token_expiry_time` 保持 None；`is_token_valid()` 因 `not self.token_expiry_time` 把早已过期的 token 判为有效，于是发出陈旧 Bearer 且 0 次 refresh。陈旧凭据的失效没有任何报错标志，属静默失效（透明刷新失效）。
